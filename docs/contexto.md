# Contexto del proyecto

## Qué es esto

Portafolio profesional de **Jennifer Muñoz**, UX/UI & Product Designer. Sitio web estático (sin frameworks ni build tools) que presenta su perfil, proceso de trabajo, habilidades y case studies de proyectos de diseño de producto.

## Stack técnico

- **HTML5 + CSS3 + JavaScript vanilla.** Sin React, Vue, ni ningún framework. Sin bundler ni paso de build: los archivos se sirven tal cual.
- **Despliegue:** GitHub → Netlify. El repo se llama `Portafolio-Jennifer-Mu-oz`, es público, y Netlify hace deploy automático desde la rama `main`.
- **Flujo de trabajo de Jennifer:** administra el repo con **GitHub Desktop** (no usa terminal/git por línea de comandos). Cuando se le entregan archivos nuevos o modificados, ella los reemplaza en su carpeta local y hace commit/push desde GitHub Desktop.
- **Formulario de contacto:** usa Netlify Forms (envío por AJAX), no requiere backend propio.

  **`netlify.toml` — excepción restaurada (septiembre 2026, tras probar en Netlify real):** con el enfoque de imagen estática + navegación en la misma pestaña, inicialmente se pensó que ya no hacía falta ninguna excepción en `netlify.toml` y se revirtió la regla `X-Frame-Options: SAMEORIGIN` que se había agregado para el embed en vivo. Eso resultó incompleto: la propia app compilada del wireframe (`assets/prototipo-vibra/`) dibuja su marco "Escritorio/Móvil" cargándose a **sí misma** dentro de un iframe interno del mismo origen — un mecanismo interno de la app, independiente de cómo `proyecto-1.html` la embebe. Bajo `file://` eso nunca falla (no hay servidor ni headers HTTP), así que todas las verificaciones con Playwright vía `file://` lo dieron por bueno; pero servido por Netlify, el `X-Frame-Options: DENY` global bloquea también ese auto-iframe del mismo sitio, dejando la pantalla en blanco con "ha rechazado la conexión" — Jennifer lo encontró al revisar el sitio ya desplegado. Se restauró la excepción, esta vez documentada con el motivo correcto: un segundo bloque `[[headers]]` con `for = "/assets/prototipo-vibra/*"` y `X-Frame-Options: SAMEORIGIN` (el resto del sitio conserva `DENY`). **Lección:** para cualquier prototipo React/Vite similar que use un mecanismo de auto-iframe (device preview, etc.), verificar también sirviendo por HTTP real (Netlify deploy preview o un servidor local), no solo con `file://` — los headers de seguridad solo existen bajo HTTP. **Origen del archivo:** Jennifer trabajó el wireframe primero en Figma Make y luego lo siguió ajustando en Claude; el proyecto **fuente** (Vite + React + TypeScript + Tailwind, no un archivo estático) vive en su carpeta local `assets/wireframe - vibra/` — esa carpeta **no se toca ni se sube al sitio**, es solo el material de trabajo de Jennifer. **Si Jennifer entrega una nueva versión del wireframe:** hay que repetir el proceso de build completo (ver `docs/diseño.md`) — recompilar, regenerar el screenshot de vista previa si la pantalla de inicio cambió visualmente, y reemplazar el contenido de `assets/prototipo-vibra/` — nunca editar esos archivos compilados a mano, son generados.
